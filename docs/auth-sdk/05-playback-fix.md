# 0.3.0 播放修复与范围

## 已确认的问题

真实 `/luna/pc/track_v2` 响应的播放模型位于 `track_player.video_model`，流地址常为 base64 编码，`video_meta` 描述音质/容器，`encrypt_info` 包含服务端按当前会话下发的播放授权。旧 stream() 只读顶层 play_url，既没解析模型，也没处理音频加密，因此显示歌曲不等于可以播放。

实测普通可播音质为 M4A/AAC，使用 CENC AES-CTR。以服务器标记为无需 VIP/购买的 medium 流验证：按该账号返回的授权解码后，ffmpeg 成功产生5秒 MP3。原始加密流不能直接当作 MP3 播放。本机 ffmpeg9不接受 `-/decryption_key`，因此不使用此选项，也不把真实密钥放到命令行。

## 实现契约

- 新 helper op `stream` 参数 `{id:string,quality:"standard"|"high"|...}`；只接收曲目 id，不接受任意音频URL、密钥、命令或文件路径。
- 用同一账号的签名请求 POST track_v2，解析真实 video_model；只选 AAC/M4A、服务端音质权限允许的流，不提升会员权限、不改服务端的限制。
- 对 need_vip 的流必须用签名 /me 验证 is_vip；need_purchase 目前没有购买证明则拒绝。显式需要 VIP 的曲目在无法确认权益时失败。缺少权限映射时保守失败；试听/时长受限不伪装成完整播放。
- 音频下载只允许已知官方 CDN 的 HTTPS 地址；最多3次受限重定向；不向 CDN 发送账号 Cookie；最大64 MiB。超限、格式不支持、解码失败都明确报错。
- 解码仅处理非分片 MP4 的 AAC CENC AES-CTR，严格解析 stsz/stsc/stco/co64/senc，样本必须落在 mdat 中，不能依靠从 mdat 顺序猜测偏移。服务端的 spade_a 在内存中转换为 AES-128 密钥；不日志/不落盘/不放进进程参数。
- 清晰音频通过私有临时文件给 ffmpeg，固定参数转为标准 MP3。ffmpeg 不接受远程URL或Shell参数，stderr不向用户透传潜在敏感元信息。
- 转码成功文件用 file:// 返回给 MyGo（它原生支持本地音频流）；权限0600，目录0700。进行有限大小/数量缓存；退出登录/进程退出清理本会话产生的文件。
- 整个准备流程限制在25秒以内，适配 MyGo30秒 stream调用时限；失败清理临时文件并终止ffmpeg，不能留下未完成输出。

## 测试计划

1. 模型解析：真实嵌套/JSON/base64、metadata与url映射、格式/加密方式拒绝、权益/付费/试用限制。
2. 授权解码：固定假密钥的往返fixture、异常长度/无效base64/非16字节密钥。
3. CENC：正常样本、混排chunk、样本表/IV数量不符、越界/重叠、截断/超大box、多个trak、无加密直通。
4. 转码：ffmpeg缺失、失败/超时、MP3输出验证、临时文件清理、返回file URL不包含密钥或原始CDN URL。
5. 插件桥：stream调用helper而非旧unsigned fetch；helper拒绝必须传给用户；不会强制报所有歌曲可播。
6. 真实验收：拿到授权的真实歌曲 -> MP3 -> 再用解码器验证非零音频样本；最终桌面是否出声须用户确认。

## 全部页面状态

此任务优先修复播放，不等于已经实现汽水所有页面。登录/首页/歌曲搜索已有验证；歌单/喜欢/专辑/歌手/分页/歌词仍需逐项接入和验收。没有验证的能力不得写成“全部支持”。

## 实际验证结果

- 播放模型的成功状态为 `status=10,message=success`，与外层 API 的 status_code 不同；已使用真实形态建立回归fixture，不能误把10当成接口失败。
- 标准音质真实样本：生成2997646字节MP3，从准备到独立解码检查约2612ms；再次解码前5秒得到441000字节PCM，样本非静音。
- 高音质真实样本：生成9016676字节MP3，约5183ms；再次解码同样通过并有非零样本。
- 以上使用用户当前插件会话、服务端返回的音质权限和授权；账号、歌曲标题、原始音频URL及密钥没有输出。
- 实际桌面是否出声仍需用户验证，不能把解码验收等同于音频设备播放验收。
- 流/加密格式参考自已有 Folia 适配及 ISO BMFF 样本表关系；仓库实现使用 Node 标准库和独立的边界检查，没有加入第三方解码器文件或任何固定内容密钥。
